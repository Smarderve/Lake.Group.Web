1. Architecture Overview

The backend is a self-hosted headless CMS (Payload 3 running inside Next.js 15) with a PostgreSQL database. It does not serve the public website — the static site keeps living at the repo root and consumes this backend's REST API.

1.2 Design Principles

  • Content owns the data; static owns the presentation. The site shell stays hand-authored HTML; the CMS becomes the single source of truth for news, leadership, companies, countries and media.
  • Public read, authenticated write. Every content collection is readable without a token (so the website can fetch it), while create/update/delete require a signed-in admin. See §5.
  • Idempotent seeding. Existing static-site data can be migrated into the CMS and re-run safely — upserts by unique keys, media uploaded once. See §10.
  • Self-hosted. No third-party SaaS; PostgreSQL + uploads persist in Docker named volumes. See §8.

1.3 What the CMS Is NOT

It is not a page builder for the whole site, and it is not deployed to Vercel with the static pages. It is a content API + admin panel that the static pages are progressively wired to consume (see §12).

3.1 next.config.mjs & tsconfig.json

next.config.mjs wraps the config with withPayload and sets output: 'standalone' so the Docker runtime only ships compiled output. tsconfig.json is strict-mode TypeScript with path aliases @/* → ./src/* and @payload-config → ./src/payload.config.ts, bundler module resolution, and JSX preserve (Next.js).

5. Access Control

All rules live in src/access/index.ts and are imported by every collection.

export const isAuthenticated: Access = ({ req: { user } }) => Boolean(user)

export const isAdmin: Access = ({ req: { user } }) => {
  if (!user) return false
  return user.collection === 'users'
}
RuleAllowsUsed by
isAuthenticatedAny signed-in admin userMedia, Countries, Companies, Leaders, News — create/update/delete
isAdminOnly users from the users collectionUsers — all operations (read included)
() => truePublic (anonymous)Read on Media, Countries, Companies, Leaders, News; Media.read
Net effect: anyone can GET public content; only logged-in admins can write. The users collection itself is fully locked down (even listing users requires admin).

6.5 Media — media

Uploaded images: news banners, gallery photos, portraits, logos, flags. Admin group Content, title field alt. Reads public; writes authenticated.

  • Storage: staticDir: 'media' → backend/media/, persisted via the Docker media-data volume.
  • Generated sizes: thumbnail 400×300, card 768×576, hero 1920×1080 (all centre-cropped).
  • MIME allow-list: image/* only.
  • Fields: alt (text, required) — everything else is auto (filename, sizes, mimeType, filesize).

8.3 Quick start

# Local dev (Postgres in Docker, CMS on host)
cd backend
npm install
cp .env.example .env            # set DATABASE_URI + PAYLOAD_SECRET
docker compose up -d db         # start only Postgres
npm run dev                     # http://localhost:3000/admin

# Production (company servers)
cd backend
cp .env.example .env            # set PAYLOAD_SECRET, POSTGRES_PASSWORD, CORS_ORIGINS
docker compose up -d --build    # migrate + cms + db

First visit to /admin shows a "create first user" screen — that becomes the admin account. Data survives restarts: Postgres in db-data, uploads in media-data.

10. Seeding Scripts

Three scripts migrate the static site's existing content into the CMS. Located in backend/scripts/.

10.1 site-data.ts — pure extraction

No Payload imports, so it can run without a database. Walks up from cwd to find the repo root (the folder containing assets/news-data.js).

FunctionReads fromProduces
loadNews()assets/news-data.js → window.LAKE_NEWSNewsSeed[] — legacyId, title, slug (slugified, deduped), date (parsed), category, excerpt, bannerImage, images, videoUrl, paragraphs
loadCountries()assets/africa-network-map.js → COUNTRY_META (regex-parsed)CountrySeed[] — key, name, ISO code, lat/lng, zoom, isHeadquarters (TZ)
loadLeaders()leadership-*.html profiles (+ order/featured from leadership.html)LeaderSeed[] — slug, name, role, unit, lede, bio paragraphs, quote, mandate, facts, photo, isLogo, featured, sortOrder
findRepoRoot / assetPath / exists—Path helpers (strips query strings, resolves relative assets, skips external URLs)
parseSiteDate / slugify / mimeFor / mediaName—Format helpers ("15 Feb, 2026" → ISO; mime lookup; basename)

10.2 seed.ts — import into the DB

Run from backend/ with npm run seed (requires a reachable database). Idempotent: upserts by unique keys — countries by code, news by legacyId, leaders by slug; re-running updates instead of duplicating.

  • Media uploaded once and cached per absolute path (ensureMedia); failures warn and continue (best-effort).
  • News galleries capped at 12 images per article (MAX_GALLERY).
  • Unknown news categories fall back to Announcements; plain paragraphs are converted to Lexical rich-text state (paragraphsToLexical).

10.3 verify-site-data.ts — dry-run checks

Run with npm run seed:verify (no database needed). Validates the extraction against real site files and exits non-zero on failure:

  • News: ≥ 30 articles, all dates parseable, slugs unique, banner paths noted if missing.
  • Countries: ≥ 9, Tanzania is HQ, all flag SVGs exist.
  • Leaders: ≥ 7, exactly one featured, all have name + role, photos exist (except logo entries).

11.3 Example — sign in (for writes)

// Payload sets a secure httpOnly `payload-token` cookie
const res = await fetch('https://cms.example.com/api/users/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  credentials: 'include',
  body: JSON.stringify({ email, password }),
})

await fetch(`https://cms.example.com/api/news/${id}`, {
  method: 'PATCH',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },

14. Security Notes & Troubleshooting

14.1 Security

  • Writes require login — read access is public so the website can fetch content; the users collection is admin-only read.
  • Strong secrets: set a real PAYLOAD_SECRET and POSTGRES_PASSWORD; never commit .env.
  • Network placement: if only internal editors manage the CMS, put it behind the company VPN/firewall rather than a public URL.
  • CORS-locked: the REST API only accepts browser calls from origins listed in CORS_ORIGINS.
  • Non-root container: the Docker runtime runs as the unprivileged nextjs user.

14.2 Troubleshooting

SymptomLikely cause / fix
DATABASE_URI connect errors in devPostgres not running → docker compose up -d db; or host should be localhost, not db
Schema missing in production bootRun docker compose run --rm migrate; or set PAYLOAD_PUSH=true once for first boot
Browser fetch blocked from the siteAdd the site origin to CORS_ORIGINS (and CSRF_ORIGINS for writes)
PAYLOAD_SECRET error on compose upMissing in .env — generate with openssl rand -base64 48
Uploads lost after container recreateShould not happen — media-data volume persists /app/media; verify volume exists with docker volume ls
seed finds wrong repo rootRun from backend/; findRepoRoot walks up to the folder containing assets/news-data.js
Seed skips a leader/news itemRun npm run seed:verify first; check output for missing banners/photos (skipped gracefully)
